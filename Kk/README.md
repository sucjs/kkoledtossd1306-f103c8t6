# KK_OLED + KK_UI 移植到本工程：流程与踩坑记录

本文记录把 KK_OLED、KK_UI 和标准 Demo 移植进 `oled/` 的完整流程，以及本次实际
暴露出、现有 skill 尚未覆盖的问题。目的是让下一次移植不必重新推导。

## 1. 本工程的接入结果

| 项 | 值 |
|---|---|
| MCU / SDK | STM32F103C8T6，STM32Cube FW_F1 V1.8.7，CMake + Ninja + arm-none-eabi-gcc |
| 总线 / 控制器 | I2C2（PB10=SCL、PB11=SDA、400 kHz）／ SSD1306 128×64 |
| 设备地址 | 7 位 `0x3C`，HAL 参数用左移后的 `0x78` |
| 列偏移 | 0 |
| 寻址模式 | 页寻址，显式 `0x20, 0x02` |
| 刷新方式 | `KK_UI_REFRESH_MODE=KK_UI_REFRESH_DMA`：命令用 IT，数据用 DMA |
| DMA 通道 | DMA1 Channel4（F103 定点映射 I2C2_TX），中断 `DMA1_Channel4_IRQHandler` |
| 输入 | PA0=上、PA1=下、PA2=确定，内部上拉、低电平有效 |
| 时基 | SysTick 1 ms，`KK_App_TickInc()` 推进 `KK_App_Millis()` |
| 资源占用 | FLASH 57864 B / 64 KB（88%），RAM 4376 B / 20 KB（22%） |

目录约定：运行时副本放在 `oled/Kk/`（`kk_oled/`、`kk_ui/`、`kk_demo/` 三棵，各自带 MIT 许可证），
平台接线放在 `oled/Core/Src/kk_app.c`、`kk_app_port.c`。`oled/Kk/` 与 `kk_oled_driver.c` 是**项目自有副本**，
构建不引用 `.agents/skills/` 下的资产目录。

## 2. 落地顺序（本次实际走的次序，可复用）

1. **先确认显示契约**：物理宽高、页数、1 bit 页式布局、控制器是否支持按页 + 列区间写入。
   本工程旧库 `kkoled0.96iic库/oled.c` 是 8 页 × 128 列、1 bit 页式，满足 KK_OLED 的核心门槛。
2. **确认硬件事实**：地址、地址表示（7 位/8 位）、列偏移、总线实例、引脚。逐项标注来源
   （工程源码 / 原理图 / 数据手册），不采信"常见模组大概是这样"。
3. **移植前确认**：把已知信息、待确认信息、阻塞/IT/DMA 现状摆给用户，等回答后再动硬件相关代码。
4. **装运行时**：复制 `kk-oled-runtime`、`kk-ui-runtime` 到项目源码树，保留许可证。
5. **改写 driver**：只改 `driver/kk_oled_driver.c` 的硬件参数与 HAL 调用，不动 graphics 与公共 API。
6. **装应用**：复制标准 Demo，按 `OLED_Init()` → `KK_UI_AppReset()` → `KK_UI_Init()` 顺序接入，
   主循环 `KK_UI_AppUpdate` → `KK_UI_Update` → `KK_UI_AppProcessEvents`，顺序不可颠倒。
7. **接平台**：时基、按键归一化、DMA/中断与 HAL 回调转发、中断 NVIC。
8. **同步生成配置**：把按键、DMA、NVIC 同时写进 `.ioc`，并把新源码接进 CMake，使重新生成不丢改动。
9. **分层验证**：静态检查 → 本机全量构建 → 字模覆盖检查 → （有硬件时）烧录与实屏验收。

## 3. 本次踩到的坑

### 3.1 寻址模式必须与差分刷新匹配（功能级，只在本场景暴露）

旧库整帧刷新每页固定写满 128 字节，`0x20` 参数字节填的是 `0x10`（水平寻址），
靠列地址在页末尾回绕到下一页，**碰巧正确**。KK_OLED 只发送每页的差异列区间，
水平寻址下 `0xB0|page` 不生效，数据会落到错误的页。

- 症状：进任何界面后局部刷新错位/残影，整帧刷新的初始化却能正常显示。
- 修法：`0x20` 参数显式写 `0x02`（页寻址），不依赖上电默认值，也不照抄整帧库的取值。
- 教训：**从整帧库转录初始化序列时必须重算寻址模式**，这类缺陷不会在照抄时被察觉。

### 3.2 中断上下文里发起下一阶段，HAL 仍可能阻塞

HAL 的 `HAL_I2C_Mem_Write_IT/_DMA` 进入时会用 `HAL_GetTick()` 轮询总线空闲。
若总线上挂死，且本中断抢占优先级高于 SysTick，tick 不再前进，超时永不触发，
就会在中断里自旋。正常路径只多几十 µs，但这是设计层面的时序违规。

- 现状：本次保留原结构（正常路径代价可接受），已在 `kk_oled_driver.c` 的
  `OLED_DriverHandleMemTxComplete` 上方写明该约束与替代方案。
- 彻底修法：回调里只置「待发起」标志，由主循环在空闲后调用驱动入口。

### 3.3 显示故障恢复必须限速

`KK_UI_RecoverDisplay()` 会把下一帧直接排到 `last_update`。若每次拿到
`KK_UI_DISPLAY_ERROR` / `KK_UI_DISPLAY_TIMEOUT` 就立刻调用，总线持续异常时
会按主循环频率反复重画重发，CPU 被占满且屏幕一直不更新。

- 修法：应用层加最小重试间隔（本工程 1 s），未到点的失败帧直接丢弃。

### 3.4 去抖必须按毫秒计时，不能按调用次数

主循环远快于 1 ms 时，用「调用次数」累加去抖窗口，实际窗口会被压缩到几乎为 0。
改为记录原始电平变化时刻 `s_key_changed_at[]`，与 `now` 比较。

### 3.5 委托 DriverInit 的早退分支是不可达的

驱动内「找不到脏页就返回」的分支，因核心只在存在差异页时才调用驱动、判定谓词相同，
实际不可达。保留早退语义的同时已在代码里标注这一调用契约；若被别的方式调用，
这里不发完成通知会让核心异步等待悬空。
